# neo_cortex

## Purpose

- The Neo-Cortex Python package: embedded/external FalkorDB store, schema, local models (GLiNER2.5 extraction/classification, EmbeddingGemma embeddings), and later the memory/retrieval/MCP layers.
- Design rules come from `knowledge/architecture/unified-plan.md`: no LLM inside the system; hybrid retrieval fused with RRF.

## Ownership

- Owns everything under `src/neo_cortex/`. Tests (`tests/`), `scripts/` and `pyproject.toml` at the repo root support this package and follow this doc.

## Local Contracts

Built (Phase 0 and the Phase 1 write path):
- `config.py`: `settings()` reads env at call time. `NEO_HOME` (default `~/.neo-cortex`, holds `neo.rdb`), `NEO_FALKORDB_URL` (if set, use that server and skip the embedded one), `NEO_PORT` (6390), `NEO_TENANT` (`default`), `NEO_DEVICE` (`auto` = cuda if available, CPU fallback on CUDA OOM; explicit `cuda` raises instead), `NEO_GLINER`, `NEO_EMBED` (repo-local model dir if present, else the Hub id). Default model dirs resolve against the repo root (`config.ROOT`), never the cwd.
- `store.py`: `Store` (context manager). Embedded falkordblite listens on TCP `127.0.0.1:NEO_PORT` only (redislite defaults to all interfaces, so `bind` is always passed). `graph(tenant)` returns graph `neo_<tenant>` and runs `ensure_schema` once per tenant; `query(cypher, params, tenant)` returns `result_set`. `close()` shuts the embedded server down unconditionally (redislite's own close skips it while another client such as FalkorDB Browser is attached) and waits for the pid; it takes about 3 s because the server module teardown is slow. Close every `Store` before exit, otherwise an orphan `redis-server` stays. One owner per home: the embedded `Store` takes an exclusive `flock` on `<home>/.lock`; a second process gets a RuntimeError naming the home; nested `Store`s in one process share one handle (refcounted, the server stops at the last close). `write_lock` (`threading.RLock`, process-wide) is the write lock: hold it around every check-then-create write section (`write.ingest_path` per document, `ingest_session`, `remember`, `dream`). Any new writer (e.g. `tools.relate`) takes `store.write_lock` too.
- `schema.py`: `ensure_schema(graph)` is idempotent. Vector indexes (768, cosine) on `Memory/Chunk/Entity.emb`, full-text on `Entity.name` (fuzzy name lookup only, it is not BM25), range indexes on `id` for Memory/Chunk/Entity/Document/Session/Agent/Handoff/Judgment, plus `Entity.key`, `Entity.type`, `Memory.created_ms`, `Memory.valid_from_ms`, `Chunk.date_ms`, `Document.date_ms`. Only "already indexed" errors are swallowed.
- `models.py`: lazy thread-safe singletons. `gliner()`; `embed_docs(texts, titles=None)` uses `title: {title or 'none'} | text: {text}`; `embed_query(text)` uses the `SearchQuery` prompt; both return float32 L2-normalized 768-d. Text-only load (vision/audio configs None, pillow + torchvision must still be installed). The model is forced to float32 (the checkpoint default is bf16, which gives unit norms of about 1.003 and the GTX 1660 Ti has no bf16). `embed_images(paths)` lazily loads a separate full model. Handles are `_Guarded` proxies: under `auto`, a CUDA OOM at load time loads on CPU; at inference it empties the cache, retries once, then moves that model to CPU for the rest of the process (one stderr warning).
- `util.py`: `new_id(prefix)`, `now_ms()`, `content_hash(text)`, `normalize_key(name)` (the Entity.key rule: casefolded, runs of non-word characters and `_` become one space, non-ASCII letters kept, so 田中 stays 田中; a name with no letters or digits gets an empty key and never creates an Entity).
- `cli.py` (`neo`): `serve [--port --warm]`, `status`, `jobs [id]`, `brief`, `recall -k`, `ask`, `who`, `timeline`, `explore`, `connect`, `impact`, `relate HEAD TYPE TAIL [--supersede|--end]`, `read`, `remember [--kind --entity name:type --rel 'head|TYPE|tail' --project]` (project defaults to the cwd basename), `ingest [--wait]` (a directory prints its job id at once; `--wait` follows it, retrying transient poll errors for up to 2 min; exit 2 with a warning when nothing was ingested and files were unsupported or failed), `ingest-session`, `handoff --to`, `cypher`, `dream [--dry-run]`, `hook session-start|session-end|pre-compact`, `install-claude [--scope user|project] [--yes]`; tool commands take `--tenant` (only `[A-Za-z0-9_-]+`, checked before any network call) and print the tool's text (`ingest-session` prints JSON). `neo status` prints `jobs:` counts and `graph is empty` when the graph has no nodes. The embedded DB has one owner, the daemon, so every command first POSTs to `NEO_DAEMON_URL` (default `http://127.0.0.1:8765`) and opens a local `Store` only on connection refused to the default URL (a timeout, an HTTP error or an explicitly set `NEO_DAEMON_URL` is an error, never a fallback; a home locked by a daemon prints the lock message, exit 1). Hooks read Claude Code's hook JSON on stdin, import no heavy module, and never fail the session: any error or no daemon means exit 0 with no output. `session-start` prints `hookSpecificOutput.additionalContext` with the brief (`project` = basename of `cwd`, `agent` = `NEO_AGENT` or `claude-code` so handoffs to the role show); `session-end`/`pre-compact` POST `ingest-session` with `background: true` (agent `NEO_AGENT` or `claude-code:<session_id[:8]>`) and return in about 60 ms. SessionEnd's default hook budget is 1.5 s, so the installed hooks set `timeout` (15/5/5 s). `install-claude` prints the hooks JSON and the `claude mcp add` command; only `--yes` merges (idempotently) into the settings file. Hook docs: https://code.claude.com/docs/en/hooks. Integration files: `integrations/claude-code/` (`settings.hooks.json`, `README.md`).
- Daemon HTTP routes (`mcp_server._add_api`, same port as `/mcp`, loopback): `GET /health` (`{ok, queued, done, errors, pending}`), `POST /api/<tool>` for the 15 tools in `API_TOOLS` (JSON args, returns the tool's text; 400 bad args, 404 unknown tool), `POST /api/ingest-session` (`transcript_path, agent, project, tenant`; `background: true` queues it, otherwise runs inline and returns JSON), `POST /api/ingest` with `background: true` (returns `{queued, job}` at once). Background jobs (`mcp_server.Jobs`, one worker thread, the last 100 finished kept, unfinished never evicted, any `BaseException` marks a job `error`) are listed by `GET /api/jobs[?id=]` with `status` queued|running|done|error and `result`; `neo jobs` prints them. POSTs need `Content-Type: application/json` and a loopback `Host` (blocks CSRF and DNS rebinding from web pages). A non-loopback `--host` is refused unless `NEO_ALLOW_REMOTE=1` (then a warning); an /api body over 1 MB gets 413; a TypeError raised inside a tool is 500, only bad argument names are 400.
- Data conventions: times are epoch-ms ints (no `datetime()` in falkordblite Cypher); vector `score` from `queryNodes` is a distance (smaller is nearer).

### Graph data model (binding for every module; change it here first)

All nodes carry `id` (str). Times are `*_ms` epoch-ms ints. Each tenant is its own graph, so there is no tenant property.

- `Document {id, kind: doc|adr|ticket|chat|meeting|session|file|code, title, uri, path, author, date_ms, status, labels: [str], hash, doc_type (frontmatter `type`, e.g. Decision), description (frontmatter; also prepended to the first chunk text), tags: [str]}`; `code` = a .py file (one chunk per top-level def/class, title = module path from the package top, e.g. neo_cortex/tools.py)
- `Chunk {id, doc_id, pos, text, kind, date_ms, emb}`: `kind` and `date_ms` are copied from the Document. The date is the *document* date, not the ingest time.
- `Entity {id, key, name, type, type_votes (JSON {type: [weight, pin]}), aliases: [str], emb, first_seen_ms, last_seen_ms, mentions}`: every named thing, people included (`type: person`); `type` is the winner of `type_votes`. `key` is the normalised name (lowercase, collapsed whitespace and punctuation). Types: person, team, service, component, file, config_setting, ticket, customer, product, tool, incident, decision, other.
- `Memory {id, text, kind: episodic|semantic|procedural|preference|decision, confidence, created_ms, valid_from_ms, valid_to_ms, status: active|superseded|merged, uses, last_used_ms, decayed_ms, source_id, agent, project, emb}`
- `DreamRun {id, at_ms, merged, promoted, decayed, conflicts}`: one per real `dream()` run (see Built: dream.py).
- `Session {id, agent, project, started_ms, path}`, `Agent {id, name}`, `Handoff {id, summary, tasks: [str], status: open|done, created_ms}`
- `Judgment {id (= content hash), question, result (json str), created_ms}`: cache for GLiNER yes/no or choice decisions.

Edges:

- `(Document)-[:HAS_CHUNK]->(Chunk)`; `(Chunk|Memory)-[:MENTIONS {conf}]->(Entity)`
- `(Entity)-[:REL {type, conf, source_id, valid_from_ms, valid_to_ms}]->(Entity)`. `type` is upper snake from a whitelist: OWNS, MEMBER_OF, DEPENDS_ON, CAUSED_BY, FIXED_BY, APPROVED, DECIDED, PART_OF, WORKS_ON, REPORTED, REPLACED_BY, RENAMED_TO, RELATED_TO. It is one relationship type with a `type` property, so Cypher never builds types from strings.
- `(Entity {type:'person'})-[:AUTHORED]->(Document)`, `-[:PARTICIPATED]->(Document)`
- `(Memory)-[:DERIVED_FROM]->(Chunk|Session|Memory)`, `(Memory)-[:SUPERSEDES]->(Memory)`, `(Memory)-[:MERGED_INTO]->(Memory)`, `(Memory)-[:CONFLICTS_WITH {found_ms}]->(Memory)`, `(Agent)-[:WROTE]->(Memory)`, `(Session)-[:BY]->(Agent)`, `(Handoff)-[:FROM]->(Agent)`, `(Handoff)-[:TO]->(Agent)`

### Module APIs

Contract refinements made while building the write path (the model above stays authoritative; these are additions):

- `Entity.aliases` holds normalised keys (not display names). `Session` also carries `hash` (transcript content hash, idempotence).
- `Chunk.id` is `<doc id>#<pos>`; `Document.id` is the frontmatter `id` (else a hash of the path). `REL.source_id` is the chunk id for extracted edges, the memory id for edges written by `remember(relations=)`, or the given `source` (else none) for `relate`; `REL.valid_from_ms` is the document date; `REL.valid_to_ms` (absent while current) is set at ingest for single-valued relations (OWNS per target, MEMBER_OF per person) when a later-dated document names a different counterpart.
- `Entity.mentions` counts MENTIONS edges from Chunks and Memories; `first_seen_ms`/`last_seen_ms` come from the mentioning chunks' document dates. They are recomputed for every entity an ingest touches.
- Entity types: every mention is a vote for (type, weight, pin): GLiNER weight = confidence, pin 0; ticket/ADR/INC ids, title ids, table cells and AST components pin 1; frontmatter author/participants and caller-given types pin 2. `type` is the highest pin, then the largest summed weight, then `resolve._RANK` on ties; `other` counts only when no other type has a vote. Any DEPENDS_ON endpoint becomes `service`.

- `extract.py`: `ENTITY_LABELS` / `REL_LABELS` map descriptive GLiNER labels to contract types (`RELATED_TO` is whitelisted but never extracted). `extract(text) -> {"entities": [{name, type, conf}], "relations": [{head, type, tail, conf}]}`, `extract_batch(texts, titles, authors, teams, kind)` (batched, long texts split by the library at 384 words; `kind` is the document kind), `classify_memory(text) -> (kind, conf)`, `worth_keeping(text) -> float` plus `_batch` forms. Choices that matter: classification labels are long descriptive phrases and the full softmax distribution is read (`multi_label=True, cls_threshold=0, class_act="softmax"`); `worth_keeping` is GLiNER label mass nudged by surface cues (the base model alone was about 70% right on a 16-sentence probe). Entity confidence floors are per type (person 0.6 up to 0.85 for component/product/decision), relation floors 0.6 (PART_OF/WORKS_ON 0.7). Junk filter: stop-list, single generic class nouns (`is_generic`: entity, graph, module, tool, model, team, ...; public, also used by retrieval), more than 4 words, and for fuzzy types (component, config_setting, other, product, team, customer, decision, incident) a proper-noun shape (capital letter or `- _ . /` or digit). Ticket/ADR/INC ids are regex-extracted and override GLiNER's type. `_sane_type`: a name with a known file extension or a path separator is `file`, and a GLiNER file is kept only as a repo path (`_repo_file`: a code, doc or config extension, or Makefile/Dockerfile/package.json/tsconfig.json; data dumps such as .txt .json .csv .rdb are dropped, the text stays in the chunk); a `person` with digits or not capitalised words, and a `customer` that is a lowercase slug or has digits, become `other`. Relations are extracted per sentence window (up to 40 words) instead of per chunk, from GLiNER (floors above; OWNS/MEMBER_OF only from a sentence that asserts it, never with a former-state cue such as `former`, `used to`, `until`, `handed over`) plus deterministic patterns over entity placeholders (`_PATTERNS`: owns/owner of/responsible for/on-call for, moves from/to, depends on/calls/uses/needs/reads from, `downstream of`, `X that Y consults`, rename/formerly/now called, replaced by, approved/signed off, decided by, caused by/root cause (`_INC`); `Decided by:`/`Approved by:` and `made the decision` target the document's own ADR/ticket id taken from its title, `_SELF`). `It`, `its`, `the service` and `this/that service` are the chunk's most-mentioned service (`topic`, moved by sentence-initial services). A passive or subject-less dependency (`goes to X`, `is written into X`, `hands them to the broker`) takes `topic` as head (`_PASS`). `X is the message broker` makes "the broker" in that document name X. An `Owner: <person>` line yields OWNS to the service named on that line, else (unless the doc kind is ticket, meeting or chat, where it is the task's owner) to `topic`. Markdown tables are read row by row (`_table_facts`; a row is a header only when a `|---|` line follows it: Owner column -> OWNS, Team column -> MEMBER_OF, Depends/Upstream/Calls/Uses/Needs/Reads cell -> DEPENDS_ON). Pattern hits have conf 0.9. An effective date (`_eff_ms`: one date after `effective`, `from`, `starting`, `as of`, `since`) becomes `valid_from_ms` of OWNS/MEMBER_OF/RENAMED_TO edges, and `_supersede` closes the previous owner at that date, not at the document date. Quality yardstick: `eval/graph_quality.py` (REL precision and recall per type against `data/synthetic/WORLD.md`; the product never reads WORLD.md). Both ends must be among the surviving entities (a unique first name, last name or tail word such as "gateway" maps to its entity) and obey head/tail type constraints (`rel_ok(type, head_type, tail_type)` over `REL_TYPES`, the single check for GLiNER, pattern and table relations; DEPENDS_ON ends may be service/component/tool/product). `<word>-service/-gateway/-cache/...` names are regex-extracted as services. Generic phrases (`_GEN_HEAD`/`_GEN_TAIL`: "other services", "Platform engineer", "config file") are dropped. Markdown tables with an `Owner` column yield OWNS edges at conf 0.9.
- `resolve.py`: `resolve_entity(store, name, type, emb=None, tenant=None, weight=1.0, pin=PIN_VOTE) -> id | None` (None for an ambiguous lone surname or an empty key; each call adds one type vote), `resolve_many(store, [(name, type[, weight, pin])])` (batches the embeddings), `judge(store, question, text, labels, tenant=None) -> {label: prob}` cached as `Judgment` (id = content hash). Order: exact key, alias, (code identifiers, `is_code`: underscore, call parens, dotted attribute, camelCase, stop here: exact only), lone first/last name of a unique person, `variant_key` (spacing, case, punctuation ignored, letters/digits split, a trailing base/large/small/tiny/medium/hf or v0/v1 dropped: `GLiNER 2.5 base` = `gliner2.5-base-v1`, `api v2` stays apart), Entity vector neighbours (similarity = 1 - distance, at least 0.85) that pass a lexical guard (same words up to plurals, or a tail/head name part, equal digits, person names never fuzzy-merge); at or above 0.92 merge, between 0.85 and 0.92 the judge may only veto (`same` below 0.5). GLiNER2.5-base is close to chance as a same-entity judge on bare names, so it is never trusted to create a merge.
- `write.py`: `ingest_path(store, path, tenant=None) -> {documents, skipped, chunks, mentions, rels, errors, unsupported, new_entities}`; `chunk_text(body, kind)`; `remember(...) -> {id, status: created|reinforced, kind, entities, conflicts: [{id, text, sim}]}` (extra optional args `confidence`, `valid_from_ms`, `entities` [{name, type}] and `relations` [head, TYPE, tail], which are linked as MENTIONS; with `kind` plus any of about/entities/relations GLiNER does not run; the result adds `entity_ids` {name: id}; cosine at or above 0.92 reinforces unless the texts differ in a number or a negation (`_differ`); such near-duplicates and 0.75 to 0.92 with a shared entity come back as `conflicts` while the new memory is still created; `supersedes` skips dedupe, links SUPERSEDES and retires the old memory); `ingest_session(store, transcript_path, agent="claude-code", project=None, tenant=None)`. Documents: frontmatter per `data/synthetic/WORLD.md` section 0; chunks of 120 to 250 words on paragraph boundaries (chats on message boundaries); unchanged hash is skipped, a changed one is replaced; the hash is written last, so a failed ingest deletes its partial Document and chunks and re-raises (the next run retries); a frontmatter `id` already owned by a document at another path counts as an error (`id collision with <path>`) and the second file is skipped; frontmatter `labels` that equal an existing Entity key add a MENTIONS from every chunk; non-markdown goes through `anydoc.to_markdown`; images and `__pycache__` are skipped. `.py` files are kind `code`: `_code_chunks` (stdlib `ast`) makes a header chunk (docstring, imports) and one chunk per top-level def/class, title = module path from the package top, def/class names become `component` entities, GLiNER reads only docstrings and comments. Titles: frontmatter `title`, else the first `# heading`, else `<parent>/<stem>`. Frontmatter `type`, `description`, `tags` are stored as `doc_type`, `description`, `tags`; the description is prepended to chunk 0. Sessions: `ingest_session` stores the candidates of `session_mem.select` (up to 15) through `remember` with `valid_from_ms` = the message time, `project` = cwd basename, `DERIVED_FROM` the Session, `(Session)-[:BY]->(Agent)`, `(Agent)-[:WROTE]->(Memory)`; the session hash is written last, so a crashed ingest is retried; an unchanged transcript is skipped, a grown one adds new memories without bumping `uses` on ones already derived from it. Result: `{session, skipped, segments (events), memories, reinforced, kinds}`.
- `session_mem.py` (pure functions, deterministic first, GLiNER only scores and types): `read_transcript` (user/assistant text, tool use, tool errors; meta, thinking, hook/command noise, code fences, sub-agent hand-backs dropped; sidechain lines dropped unless the file has no main-thread line: a sub-agent file, whose sidechain lines are the conversation, first user line is the parent's brief and session id is the file stem), `units` (sentence units that read alone: headings and short labels dropped, a lead-in ending in `:` merged into its bullets unless it holds a pronoun, a dangling sentence (`It/This/They/Also/Since then ...`) takes the previous sentence else is dropped, bullets with no verb under a lead-in dropped), then candidates: user `preference` (normative cue or imperative such as always/never/don't/prefer/use X/stop, corrections right after an assistant action, user's words with fillers stripped; at most 5, 4 to 40 words, tasks and questions excluded), `decision` from either side (decided/chose/going with/dropped, reason from the same or next sentence), `procedural` lessons (`the cause was`, `fixed by`, and `When <cmd> failed with <err>, <explanation>` only when the assistant explains it right after the failure with a word shared with the command or error and a later step succeeds), and `episodic`/`semantic` outcomes from assistant closing text (or any assistant text of 60+ words): 8 to 60 words, concrete (number, path, backtick, name), no chatter (`I'll`, `Let me`, `Now`), questions, second person, imperatives, ephemeral status (`still running`, `/tmp/`) or unresolved `they/them/the old one`. Assistant text is rewritten to third person (`I added X` becomes `The agent added X`; present-tense `I think` is dropped). `select` scores `worth_keeping` + features (number, path, backtick, name; preference +0.3, pattern +0.15), requires worth+features >= 0.55 for outcomes and >= 0.3 for decisions/lessons, removes near-duplicates (token overlap >= 0.75), keeps preferences first, 15 in total; outcome kind comes from `classify_memory_batch` (an event kind needs a past-tense marker, else `semantic`). Measured on this project's real transcripts: about 85% of the stored memories were useful, standalone and plausibly typed (small sample, hand-judged). `_keep` (before scoring) drops fragments (lowercase/dangling starts, subordinate openers, bare `label:` leads, trailing `, which ...` clauses, under 8 words) and plans (`I will`, `Let me`), except preferences and decisions; a time-bound status (`is committed`, `currently`, `today`) makes an outcome episodic.
- `tools.py` (agent tools, plain text with ids): `impact(entity, max_hops=3)` (hops clamped to `MAX_HOPS`=5, as are `connect` and the `ask` bridging paths) walks current `DEPENDS_ON` edges (`valid_to_ms IS NULL`) both ways by a Python BFS (one query per hop; a cap beyond max_hops is reported), with hop, path, source per edge, the deduplicated current `OWNS` owners (team members listed) and customers (type `customer` only); `relate(head, type, tail, source, supersede, end, agent)` only whitelisted `REL_NAMES`, resolves or creates entities, `end` closes the current edge(s) (`valid_to_ms`, no replacement, kept as history), and `supersede` is allowed only for single-valued types (OWNS: other owners of `tail`; RENAMED_TO/REPLACED_BY: other edges of `head`) and refused for the rest, and returns what it closed; `remember(entities, relations)` writes each relation through the same `_edge` helper (`relate` body) with source_id = the memory id; `read(id)` gives the full Chunk, Memory or Document with neighbours (`prev`/`next` ids for chunks, supersedes links for memories); `timeline` opens with "Changes:" (the 12 strongest change records, `YYYY-MM-DD [doc id] text`, from recall hits and the entity's chunks: a number or change verb, naming at least two topic words, or a change verb alone in an entity chunk; short bullet fragments join their sentence; plural `s` ignored), then "Events:" (REL changes with effective dates, superseded memories); each event query reads only its newest 200 rows and the render is cut once. Every public tool is wrapped by `tools._guarded`: an invalid `tenant` or a bad `since`/`until` (`bad date`) returns text, never an exception. `ask` and `explore` show ended edges as `ended YYYY-MM-DD`, and `connect`/`ask` bridging skip paths through ended edges (shortcut: SPpaths over-fetches 4x, so a current path longer than that is missed). `cypher` puts the LIMIT into the query (the query's own smaller LIMIT wins). `who` links an exact `Entity.key` only when one exists, and ranks current direct OWNS (or MEMBER_OF of an OWNS team) first. Entity resolution and writes go through `resolve.resolve_entity` and `write.remember`. Hit text in `recall`/`ask`: `_full_text` re-reads each hit's full Chunk/Memory text by id (retrieve trims to 400 chars) and `_snip(text, query, 240)` prints the 1-3 sentences sharing most query terms (`channels._tok`, split by `write._sentences`), in document order with ` … ` across gaps, else the head.
- `retrieve/`: channel functions return ranked `[(node_id, score)]`; `rrf(lists, weights, k=60)`; `parse_query(q) -> {entities, intent: {label: conf}, since_ms, until_ms}`; `recall(store, query, k=8, since_ms=None, until_ms=None, kinds=None, weights=None, channels=None, tenant=None, now_ms=None, info=None) -> [{id, label, text, score, channels: {name: rank}, paths, source (Chunk: doc_id, title, kind, uri, author), date_ms, kind, status}]`. Choices that matter:
  - Time: only explicit expressions (ISO dates, months, "last N days", "yesterday", "since/before ...") become windows; invalid calendar dates (`2026-02-31`, `December 9999`) are skipped. "today/now/current/latest" are recency cues (`RECENT_RE`) that switch the temporal channel on, never filters. A window parsed from the query that yields no result is dropped and the search repeated with a stronger temporal weight; explicit `since_ms/until_ms` arguments stay hard.
  - Linking (`link_entities(...) -> {id: (name, conf)}`, at most 5): exact key (1.0 GLiNER, 0.7 query n-gram), fuzzy name (0.8 x ratio), a rare content word shared with an entity name (0.35 to 0.5), nearest embedding (0.6) only when at least 0.9 or at least 0.8 with a shared content word. Generic role/kind words (`_GENERIC`) never link fuzzily. In `graph`, links below 0.65 are kept only if the entity is mentioned by a top dense/BM25 hit.
  - Graph channel = HippoRAG-style Personalized PageRank (`channels.ppr`, numpy over a local subgraph of at most 3 expansion hops and 500 nodes, checked as nodes are added within a hop, with REL reads capped at the 1000 strongest per hop and at most 25 chunks per entity). Walk: entity to REL neighbours (conf, undirected, only edges without `valid_to_ms` unless the query is temporal) with 50% of its mass, else to its chunks; chunk to its entities weighted by conf times specificity squared (`1/ln(1+mentions)`), so hub entities carry little. Reset vector = 50% linked query entities + 50% entities mentioned by the top-5 dense/BM25 hits (rank-decayed): query expansion through the graph. With no linked seed the channel returns nothing (no anchors-only walk). Seed strength = max over seeds of link conf x corpus-relative IDF of its mentions; below `SEED_FLOOR` (0.2) the channel returns nothing, otherwise the graph's RRF weight is multiplied by the strength (`info['strength']`). Chunks/Memories rank by PPR mass; `paths[id]` is the shortest hop path from a seed. `recall(info=dict)` receives `seeds` and the PPR-reached `entities` (used by `tools.ask`). `algo.pageRank` is not used (no personalization).
  - Fusion weights: `channel_weights` = BASE x (1 + sum intent_conf x BOOST); graph is boosted for connection/owner intent and damped for fact intent. A `decision` intent (GLiNER label, or `DECISION_RE` why/decided/reason/chose, which forces at least 0.6) multiplies fused scores of decision Memories and `adr` Chunks by `fuse.kind_factor`.

Built: dream.py (`neo dream` consolidation, no LLM):
- `dream(store, tenant=None, now_ms=None, dry_run=False) -> {id, at_ms, dry_run, merged, promoted, decayed, conflicts}`. It reads the graph once, plans in Python, then writes with UNWIND, all under `store.write_lock` so the plan cannot go stale. `dry_run` writes nothing (`id` is None). Steps, in order:
  1. Merge: active Memories of the same kind at cosine >= `write.DEDUPE` that do not differ in a number or negation (`write._differ`: "rate limit 200" never merges into "100"). The oldest is canonical; `uses` is summed; MENTIONS and DERIVED_FROM are re-pointed to it; the duplicate gets `status: merged` and `MERGED_INTO`. Nothing is deleted.
  2. Promote: an episodic cluster (cosine >= 0.80 around a seed) seen in >= 3 distinct Sessions becomes one `semantic` Memory. Its text is the most-used member's, `confidence = min(0.95, 0.5 + 0.1 * sessions)`, it is `DERIVED_FROM` each member, and its MENTIONS are the union. Skipped when a member is already a source or an active semantic is >= 0.92 similar.
  3. Decay: active, non-preference/decision Memories unused for whole 30-day periods (anchor = max(`last_used_ms`, `decayed_ms`)) get confidence x0.9 per period, floor 0.1, and `decayed_ms` is set. Never raised, never deleted.
  4. Conflicts (the same rule as `remember`'s conflict flags): active pairs of any kind that differ in a number or a negation (`write._differ`) at cosine >= 0.92 (no entity needed) or at 0.75 to 0.92 with a shared entity get `CONFLICTS_WITH`. Nothing is resolved; the agent decides via `remember(..., supersedes=)`.
  5. Every real run writes a `DreamRun` (even all-zero counts). A rerun changes no Memory or edge.
- Retrieval excludes `status: merged` always (`retrieve/channels.py` `keep`; `timeline` memory rows too). `superseded` stays hidden unless temporal intent.

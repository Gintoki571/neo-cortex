The problem and the 30-second pitch

AI agents forget everything between sessions, and the knowledge they need lives in documents, tickets and chats they cannot see as a whole. Neo-Cortex is one FalkorDB graph that is, at the same time, an agent's long-term memory, a company brain built from documents, and a reasoning layer that answers multi-hop questions. Agents use it through an MCP server (15 tools) or the neo command line. There is no LLM inside: two small local models — GLiNER2.5 for extraction and decisions, EmbeddingGemma for embeddings — do the fast "System 1" work, and the calling agent (Claude) does the reasoning. (docs/judges-guide.md §1)

Track 01 — Agents that act on connected data

ask returns an evidence pack (seeds, graph paths between them, facts, cited chunks); connect, impact, who walk the graph.

Track 02 — Agent memory & coordination

Typed memories, Claude Code hooks that brief at session start and extract at session end, handoffs between agents, dream consolidation.

Track 03 — Company brain

Docs, tickets, ADRs, chats and meetings in one graph; who finds owners and experts; timeline traces decisions to their sources.

"It puts what an agent learns and what a company knows into one typed graph, answers the questions files alone cannot — who owns it now, what changed, what breaks if this dies — and shows its work: every answer carries ids, sources and dates."

System architecture

One local process owns the graph and the models. Agents reach it over MCP (streamable HTTP on 127.0.0.1:8765/mcp) or through the neo CLI and Claude Code hooks, which call the same daemon's /api routes. Every tenant is its own graph neo_<tenant>. (docs/architecture.md, src/neo_cortex/store.py)

Click any box for details. The daemon is the only process that opens the database; CLI commands fall back to a local store only when no daemon answers. (docs/architecture.md, src/neo_cortex/AGENTS.md)

The 15 MCP tools

Each tool returns token-budgeted text with ids, sources, dates, confidence and the channels or paths that matched. (README.md; src/neo_cortex/mcp_server.py API_TOOLS)

Smoke test: 15 of 15 tools OK end to end; schemas cost ≈ 2,077 tokens of agent context. eval/mcp_smoke.md

The neo CLI (for humans and coding agents)

Every tool command POSTs to the daemon's /api/<tool>; a local store opens only when no daemon answers (connection refused on the default URL). Hooks never open the database and never fail the session. (src/neo_cortex/cli.py)

Data model (entity–relationship)

Every node has an id string; times are *_ms epoch-millisecond integers; each tenant is its own graph, so there is no tenant property. One relationship type REL carries a type property, so Cypher never builds types from strings. Binding contract: src/neo_cortex/AGENTS.md; created by schema.py (768-d cosine vector indexes on Memory/Chunk/Entity.emb, full-text on Entity.name, range indexes).

Audit nodes: Judgment caches GLiNER yes/no and choice decisions (pg-jev idea); DreamRun logs each real consolidation run; TuneRun logs each self-tuning trial (written by eval/tune.py). Click any entity for its role and code.

REL edge types and the assertion gate

OWNS MEMBER_OF DEPENDS_ON CAUSED_BY FIXED_BY APPROVED DECIDED PART_OF WORKS_ON REPORTED REPLACED_BY RENAMED_TO RELATED_TO — 13 whitelisted types on the single REL relationship. (src/neo_cortex/AGENTS.md)

Every extracted edge is gated

Its source sentence is classified fact / possibility / denial / plan; modality and p_fact are stored on the edge; denials are never written; current-state tools and the graph walk read facts only. Agent-written edges are facts.

Every edge can carry history

valid_from_ms is the document date; valid_to_ms (absent while current) closes an edge — an edge with an end date is history, skipped by queries about "now".

Write path — two ways in, on purpose

Automatic for documents nobody has read yet; direct for what an agent already knows. Why both: on this repository's own prose GLiNER found only 5 relations in 72 documents — the agent that just did the work knows the facts better than any extractor. (eval/real_check.md: ingest rels: 5; docs/judges-guide.md §4)

Both lanes converge on the same graph. Synthetic corpus ingest measured: 102 documents, 136 chunks, 97 REL edges, 130 entities in 85.5 s (eval/results.md). Real-repo ingest: 72 docs → 423 chunks, 1,166 mentions, but only 5 RELs in 307.7 s (eval/real_check.md).

Why an edge gate?

Trap probe of 25 hand-labelled sentences: base model alone 17/25; model + negation-cue rule 20/25. Fact-only relations after the gate: precision 0.880 → 0.903. (README.md "System 1 decisions")

Why a judge that can only veto?

GLiNER2.5-base is near chance as a same-entity judge on bare names, so between similarity 0.85–0.92 it may only reject a merge — never create one. A wrong merge corrupts owners and impact. (src/neo_cortex/AGENTS.md resolve.py)

Read path — four channels, one fused ranking

recall runs four channels and fuses them with weighted reciprocal rank fusion: score = Σ w_c / (60 + rank_c). Base weights 1.0 (temporal 0.5), scaled softly by the GLiNER intent of the question — one misroute nudges the ranking instead of breaking it. (README.md Retrieval; retrieve/fuse.py rrf(), channel_weights())

Graph-native tools on top of recall

Every tool accepts max_chars (default 4000); docs/neo-for-agents.md tells coding agents to keep it small and use read for full text.

Time: how text becomes history

Validity is a property, not a guess. An edge or memory carries valid_from_ms; valid_to_ms (or a supersede) closes it, and closed things stay in the graph as history. "Who owns X now" and "what changed" become graph queries instead of text searches. (README.md Graph data model; tools.py relate())

valid_from / valid_to

Extracted edges date from the document; single-valued relations (OWNS per target, MEMBER_OF per person) are closed automatically when a later-dated document names a different counterpart.

supersede

remember(..., supersedes=id) links SUPERSEDES and retires the old memory; relate --supersede closes the edge an agent corrects (single-valued types only).

end=True

relate --end closes the current edge with no replacement — "this stopped being true", kept as history, not deleted.

step 0 / 4
Press Play (or step) to move through time. The bars are what timeline "session.ttl_seconds" and who "session cache" print; older values and the former owner keep their end dates.

Retrieval hides superseded memories unless the question is about change; merged memories never surface. (retrieve/channels.py keep())

Memory lifecycle

From "the agent just learned something" to "the next agent knows it" — with an overnight-style consolidation in between. Everything below runs without an LLM.

The SessionStart hook injects the brief, so memory works even if the agent never calls remember. Hooks return in about 60 ms and never fail the session. (README.md Memory lifecycle; src/neo_cortex/AGENTS.md cli.py)

Sessions, not just explicit writes

Deterministic rules pick self-contained statements (preferences, decisions, lessons); GLiNER only scores them. Narration, fragments and plans are dropped; assistant text is rewritten to third person.

Why "dream"?

An offline, deterministic, idempotent consolidation pass — the Dream-RSI idea. A rerun changes nothing; every real run is logged as a DreamRun node. Tests cover merge, promote, decay, conflicts, idempotence and dry runs. (docs/lineage.md §3)

What we say about the losses

Graph ties text on finding documents. Recall@10 full 0.76 vs vector+bm25 0.75, delta +0.006 [−0.029, +0.040] — the CIs include 0. The graph earns its keep on structural questions, not on document retrieval. (eval/results.md)
Value-change answers: the tool loses. 0.80 vs 1.00 all-keys on the 10 change questions (−0.20 [−0.50, +0.00], inside noise but tool lower). We report it. (eval/answers.md)
Relations from real prose are sparse. 5 REL edges extracted from this repo's 72 documents — that is why agents write relations directly with remember(entities, relations) and relate. (eval/real_check.md)
Seven measured ideas were not adopted — none beat the default across both corpora (next section). (eval/flags.md)

FalkorDB is the only store. One graph per tenant (neo_<tenant>), embedded through falkordblite or run in Docker; the same Cypher works on both. Every query the product depends on is listed in docs/cypher.md with the function that issues it. (README.md, "How we use FalkorDB")

Graph algorithms in play: shortest paths (algo.SPpaths), variable-length path traversal, Personalized PageRank (HippoRAG idea, computed in numpy over a subgraph fetched with Cypher), and weighted Reciprocal Rank Fusion over four channels (k=60). Limits we state openly



  
Small evaluation
One synthetic corpus and 80 questions written by the same team that built the tools. The numbers show the design works on this corpus; they do not establish general accuracy. (README.md Limitations)

  
Relation recall
GLiNER finds many entities but misses many relations (CAUSED_BY recall 0/5 on synthetic; 5 edges in 72 real docs). Deterministic patterns recover some; the rest is absent and answers then depend on the text channels. (README.md; eval/graph_quality.md)

  
Single node
One daemon owns one graph: no replication, no multi-writer scaling, no authentication beyond loopback-only binding. Keep the daemon on the loopback interface. (README.md)

  
No LLM by design
ask returns evidence and paths; the calling agent writes the answer. Answer quality depends on that agent. (README.md)

  
BM25 rebuilds
The BM25 index is rebuilt in full whenever the corpus changes — fine at demo size, stated in the code as a shortcut to ~10k chunks. (README.md; retrieve/channels.py _bm25_index)

  
Docker volume
The compose file's persistence path for the combined FalkorDB image is not verified by a run. (README.md; docker-compose.yml)





What we would do next


Better relation extraction from real prose, an answer-grounding check, and lessons from open memory systems (agentmemory, graphify, Hindsight) for fusion and temporal reasoning. (docs/judges-guide.md §9)

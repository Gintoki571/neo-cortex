# ADR-008: Two approvals for production config changes

## Status

Accepted, 2026-08-14. Effective immediately.

## Context

Earlier this month, INC-03 caused a payments outage. The root cause was an unreviewed typo in a production config change. The change was pushed without a second look, and nothing in the path stopped it from going live.

The lesson is short. A production config change is as dangerous as a code change, and we review code. Config has to get the same treatment, with the expectation that a second person has looked at it before it goes out.

## Decision

From today, every production config change needs two approvals before it is applied. Both approvers must be people other than the author. Chen Wei and the rest of Platform will work to this rule starting now.

## Consequences

- Config changes take longer to land, because the approval step adds waiting time.
- Rollback remains the first response to a bad change, and approval is the first line of defence against one.
- The config tooling has to show clearly who approved each change, so that the record is usable in a review.
- We will watch the approval wait time and bring the rule back to the leadership group if it becomes a blocker.
- We review the rule after its first month and record the average approval wait, so the decision can be revisited with numbers.

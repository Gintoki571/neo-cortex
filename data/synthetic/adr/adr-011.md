# ADR-011: One approver plus automated validation for config

## Status

Accepted, 2026-10-06. This is a partial reversal of the two-approver rule we adopted in ADR-008. We are keeping a human in the loop, but only one.

## Context

After the August incident where a mistyped timeout went out in a production config push with nobody else looking at it, we required two approvals for every production config change. That fixed the review gap, but it made routine changes slow. Since the rule took effect, the median wait for the second approval has been 3.5 hours. Most of that time is people being in meetings or on other work, not anyone actually reading the diff.

While looking at the wait times I replayed the August change through the validator prototype. Had cfglint been running, the bad value would have been rejected before the push went out. The validator checks each config value against its declared type and range, and it runs on every change in config-service, so it does not depend on anyone remembering to look.

Mateo raised the point that a validator only catches the mistakes it knows about. Logic errors and wrong-but-in-range values still need a reviewer who understands the service. That concern shaped the decision below.

## Decision

Production config changes need one approver and a clean run of automated validation by cfglint. The two-approver requirement from ADR-008 is removed. A change that fails validation cannot be pushed, and a change that passes still needs one named approver who is not the author.

## Consequences

- Routine config changes no longer wait for a second person's availability.
- Type and range mistakes are caught mechanically. The validation rules become part of the Platform review surface and need an owner.
- Logic errors rely on a single reviewer. We accept that risk and will revisit if a second incident traces back to a reviewed change.
- The rollback path is unchanged. On-call can still roll back a key in one step with cfgctl and tell the on-call channel afterwards.
- ADR-008 is superseded for approvals. Its reasoning about the August change still stands.

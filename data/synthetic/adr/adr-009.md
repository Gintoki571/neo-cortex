# ADR-009: Idempotency key contract for events

## Status

Accepted, 2026-09-16.

## Context

Consumers of ledger events dedupe on the idempotency key, so the key has to mean the same thing every time it is seen. INC-04 showed how fragile that assumption is. When the shape of the key changed on the producer side, deduplication stopped working in the consumers, and nobody on the consuming side had a test that would have caught it before release.

I proposed this record after going back through the incident with Elif and Yusuf. The fix in the code was quick. Writing down the contract is what stops the same thing happening again next quarter.

## Decision

The idempotency key for events is `txn_id` and nothing else, and it is immutable. Retries and replays carry the same key. Any producer change that touches the key requires a consumer contract test, and that test must pass before the change is released.

## Consequences

- Retries and replays are safe to dedupe, because the key does not change between them.
- A change to the key now means a new contract and a conscious version bump, not a quiet edit.
- Each consumer adds a contract test to its own suite, and the producer runs those tests before it ships.
- The contract is referenced from the event documentation, so new consumers will find it.
